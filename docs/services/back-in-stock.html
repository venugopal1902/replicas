Back in Stock

Restock waitlists that actually notify people. Self-hosted, no $19-99/mo per store.

Replaces Back in Stock by Amp Version 0.1.0 License MIT Runtime Python 3.12

Overview#

Back in Stock by Amp charges Shopify merchants $19 to $99 a month to collect restock waitlists and email shoppers when a sold-out variant returns. This engine reproduces the core loop: per-variant waitlist signup, a restock trigger that queues one notification per waiter, preorder capture, admin stats and per-variant CSV export, plus a storefront demo and admin console. Notifications are recorded as dry_run by default and are never labelled sent unless SMTP was actually configured.

What you get

  • 20/20 checks passing against a live server

  • Admin console and storefront demo
  • Per-variant CSV export
  • Dry-run by default, never fakes a delivery

Waitlists

Shoppers subscribe to one sold-out variant with an email. Duplicate signups are reported instead of duplicated.

Restock trigger

Setting stock from 0 to positive queues a notification row for every waiting subscriber and flips them to notified.

Preorders

Capture intent on sold-out variants with quantity, independent of the waitlist.

Admin

Stats, variant list with waiting counts, notification log, and CSV export per variant.

Honest sends

SEND_MODE=dry_run records notifications without transmitting. Nothing is reported as delivered.

Interface#

Storefront at / and admin console at /admin, served by the API process on port 8600.

Install#

From a clean machine to a running server in four commands.

Requirements

  • Python 3.11 or newer
  • uv (Astral)
  • No Shopify account needed for the demo

Step 1 · Clone

Get the source.

git clone https://github.com/venugopal1902/replicas.git
cd replicas/services/back-in-stock

Step 2 · Install

Create the environment and install FastAPI.

uv sync

Step 3 · Run

Start the storefront and admin console on port 8600.

uv run python scripts/run_server.py

Run the suite with the server up

cd services/back-in-stock
uv run python tests/test_back_in_stock.py

Usage#

Join a waitlist

A sold-out variant accepts an email with no auth. A duplicate signup returns duplicate:true instead of creating a second row.

curl -s -X POST http://127.0.0.1:8600/api/public/waitlist \
  -H 'Content-Type: application/json' \
  -d '{"variant_id": 2, "email": "shopper@example.com"}'

Restock and notify everyone waiting

Move stock from 0 to a positive number. Every waiting subscriber gets a queued notification and flips to notified.

TOKEN=$(curl -s -X POST http://127.0.0.1:8600/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@backinstock.local","password":"backinstock123"}' | jq -r .token)

curl -s -X POST http://127.0.0.1:8600/api/variants/2/stock \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"stock": 25}'

Operational notes#

Read before going live. These are the things that break in production.
  • SEND_MODE defaults to dry_run. Notifications are recorded, not transmitted.
  • A real Shopify deployment additionally needs an OAuth app, inventory-level webhooks, and an SMS provider for the SMS channel.
  • The suite picks a sold-out variant dynamically, so it is safe to re-run against an existing database.

FAQ#

Does it send real email?

No. By default every notification is written with status dry_run. Nothing is labelled sent unless SMTP was configured and used.

Does it need a Shopify account?

No. Stock is set through the admin API, which simulates what an inventory webhook would do.

Blotato Engine

One REST API + MCP server to publish to 9 social platforms. Self-hosted, unlimited posts, zero subscription.

Replaces Blotato Version 0.1.0 License MIT Runtime Python 3.12

Overview#

Blotato sells a unified social media API and MCP server for $29/mo. This engine reproduces the same surface — /v2/posts, /v2/users/me/accounts, /v2/analytics, /v2/dm-automations, /v2/credits, plus a JSON-RPC MCP endpoint — on your own machine. Same request shapes, same tool names, no per-seat billing and no post caps.

replaces Blotatov0.1.0MITPython 3.12

What you get

  • Drop-in REST compatibility with Blotato v2 endpoint shapes
  • Native JSON-RPC MCP so Claude, Cursor and Hermes get the tools directly
  • Multi-tenant API keys with per-plan credit quotas and rate limits
  • Background scheduler dispatches due posts every 15 seconds
  • Six real platform connectors plus a deterministic mock for testing
  • Full credit metering wired into every publish call

Unified publishing

One POST /v2/posts call targets any connected account. The connector registry resolves the right platform adapter from the account record, so adding a platform never touches your client code.

Scheduling engine

Pass an ISO-8601 scheduledTime and the APScheduler worker picks the post up within 15 seconds of its due time. Status moves scheduled to published or failed with the platform error preserved.

MCP server

A JSON-RPC endpoint implementing initialize, tools/list and tools/call. Five tools ship by default: list accounts, publish post, get post status, get analytics, check credits.

Multi-tenant billing

Every API key carries a plan, a credit balance and an hourly rate limit. Admin keys are unlimited. Client keys stop working the moment credits hit zero, which makes resale trivial.

Real connectors

Meta Graph API for Instagram Reels and carousels, X API v2, LinkedIn UGC posts, and Bluesky AT Protocol are implemented directly. Missing credentials fall back to a deterministic mock so the pipeline is always testable.

Testable by design

A six-stage end-to-end suite exercises health, account listing, publish, status verification, key minting and MCP tool listing against the real ASGI app.

Install#

From a clean machine to a running server in four commands.

Requirements

  • Python 3.12
  • uv package manager (pip also works, uv is faster)
  • Git

Step 1 · Clone the repository

Grab the monorepo and move into the service directory.

git clone https://github.com/venugopal1902/replicas.git
cd replicas/services/blotato-engine

Step 2 · Install dependencies

uv reads pyproject.toml and creates an isolated virtual environment.

uv sync --python 3.12

Step 3 · Verify the build

Runs the full end-to-end suite. Six checks must pass before you continue.

uv run python tests/test_engine.py

Step 4 · Start the server

Binds to port 8400. Database and seed accounts are created on first boot.

uv run python scripts/run_server.py

Confirm it is live

curl http://localhost:8400/health
# {"status":"online","service":"Blotato Self-Hosted Engine"}
SurfaceURL
REST basehttp://localhost:8400/v2
MCP endpointhttp://localhost:8400/mcp
Swagger UIhttp://localhost:8400/docs

Usage#

List connected accounts

Every publish call needs an accountId. Fetch the list first; never invent IDs.

curl -s http://localhost:8400/v2/users/me/accounts \
  -H "blotato-api-key: $BLOTATO_KEY"

Publish a post immediately

Omit scheduledTime to publish on the spot. Media must be public URLs.

curl -s -X POST http://localhost:8400/v2/posts \
  -H "blotato-api-key: $BLOTATO_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "post": {
      "accountId": "<ACCOUNT_ID>",
      "content": {
        "text": "Ship faster. Post everywhere.",
        "mediaUrls": ["https://example.com/reel.mp4"]
      },
      "target": {"targetType": "instagram"}
    }
  }'

Schedule for later

Add an ISO-8601 timestamp. The scheduler fires within 15 seconds of the due time.

curl -s -X POST http://localhost:8400/v2/posts \
  -H "blotato-api-key: $BLOTATO_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "post": {
      "accountId": "<ACCOUNT_ID>",
      "content": {"text": "Tomorrow morning drop"}
    },
    "scheduledTime": "2026-11-01T09:00:00+05:30"
  }'

Connect an agent over MCP

Drop this into your client config. Any MCP-capable agent gets the publish tools.

{
  "mcpServers": {
    "blotato": {
      "url": "http://localhost:8400/mcp",
      "headers": {
        "blotato-api-key": "<YOUR_KEY>"
      }
    }
  }
}

Mint a key for a paying client

Generates a starter key with 1,000 credits and a 1,800 request/hour ceiling.

uv run python scripts/create_api_key.py \
  --client "Acme Agency" \
  --plan starter \
  --credits 1000

Operational notes#

Read before going live. These are the things that break in production.
  • Instagram and Facebook publishing needs a Meta app with instagram_content_publish and pages_manage_posts approved. Until then the connector returns a mock URL.
  • X API v2 requires a paid tier for write access. Bearer-only tokens can read but not post.
  • Media must be publicly reachable URLs. Local files need hosting first; S3 or Cloudflare R2 both work.
  • The database is SQLite. For multi-instance deployments swap DATABASE_URL to Postgres and run Alembic migrations.
  • Never expose port 8400 directly. Put it behind Nginx or Caddy with TLS before selling access.

FAQ#

Is this the same API as Blotato?

The request shapes, endpoint paths and MCP tool names are intentionally identical, so existing n8n flows and agent prompts work unchanged. Blotato's own hosted service is a separate product; this is an independent implementation you run yourself.

Can I sell access to it?

Yes. Keys carry plans and credit balances, and the API refuses writes once a key is exhausted. Mint keys with scripts/create_api_key.py, collect payment however you like, top up the balance when they renew.

What happens without platform credentials?

The connector registry falls back to a mock adapter that returns a plausible URL and status. That keeps the full pipeline testable before you have app review approval.

Does it store my tokens?

Platform credentials live in the social_accounts table as JSON alongside the account row. For production, encrypt that column or move credentials to a secrets manager.

Blotato Engine

Unified social API, MCP server and full web console for 9 platforms. Self-hosted, unlimited posts, zero subscription.

Replaces Blotato Version 0.2.0 License MIT Runtime Python 3.12

Overview#

Blotato sells a unified social media API and MCP server for $29/mo. This engine reproduces the whole surface — publishing, scheduling, comments, DMs, keyword automations, analytics, visual generation and source repurposing — across 38 REST endpoints and 17 MCP tools, plus a nine-screen web console. Same request shapes, same tool names, no per-seat billing and no post caps.

replaces Blotatov0.2.0MITPython 3.12

What you get

  • 38 REST endpoints
  • 17 MCP tools
  • Nine-screen web console
  • Nine platform connectors
  • Scheduling and weekly slots
  • Keyword DM automations
  • Six PNG templates
  • Source extraction and repurposing

Publishing

One POST /v2/posts targets any connected account. The connector registry resolves the platform adapter.

Scheduling

ISO-8601 scheduling, background dispatcher and recurring weekly slots per account.

Comments and DMs

Read comments, reply publicly, list DM threads and send messages.

Automations

Keyword triggers, public reply variants, DMs, gates and webhooks.

Analytics

Snapshots, aggregate totals, engagement rates and top-post rankings.

Visuals

Six Pillow templates render quote cards, tweet cards, carousels and infographics.

Sources

Extract from YouTube, articles, PDFs, X posts or text, then repurpose drafts.

Console

Dashboard, composer, queue, inbox, automations, visuals, sources, analytics and settings.

Interface#

Console at /, served by the API process.

Install#

From a clean machine to a running server in four commands.

Requirements

  • Python 3.12
  • uv
  • Git

Step 1 · Clone

Get the source.

git clone https://github.com/venugopal1902/replicas.git
cd replicas/services/blotato-engine

Step 2 · Install

Create environment.

uv sync --python 3.12

Step 3 · Test

Run suite.

uv run python tests/test_engine.py

Step 4 · Run

Start service on port 8400.

uv run python scripts/run_server.py

Usage#

List accounts

Fetch IDs first.

curl -s http://localhost:8400/v2/users/me/accounts -H "blotato-api-key: $BLOTATO_KEY"

Publish

Media URLs must be public.

curl -X POST http://localhost:8400/v2/posts -H "blotato-api-key: $BLOTATO_KEY" -H "Content-Type: application/json" -d '{"post":{"accountId":"<ID>","content":{"text":"Hello"}}}'

MCP

Connect an agent.

{"mcpServers":{"blotato":{"url":"http://localhost:8400/mcp","headers":{"blotato-api-key":"<KEY>"}}}}

Operational notes#

Read before going live. These are the things that break in production.
  • Real credentials rejected by a platform fail honestly; only provider=mock accounts simulate.
  • Live posting needs approved platform apps and valid tokens.
  • Use TLS and change the master key before public exposure.

FAQ#

Is this affiliated with Blotato?

No. Independent clean-room implementation.

Does mock publish live?

No. Demo posts carry simulated=true.

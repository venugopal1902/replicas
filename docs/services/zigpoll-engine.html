Zigpoll Engine

Post-purchase surveys with a public embed separated from admin credentials. Signed webhooks included.

Replaces Zigpoll Version 0.1.0 License MIT Runtime Python 3.12

Overview#

Zigpoll sells post-purchase surveys and response analytics for Shopify merchants. This engine reproduces the part that actually matters: four distinct question types, survey create/update/list, anonymous public responses keyed by a public survey id that is separate from the admin credential, authenticated admin reads, aggregates computed from raw rows, CSV export, and HMAC-SHA256 signed webhooks that refuse plain-HTTP destinations. A bad signature is rejected, and the test suite proves it rather than asserting it in prose.

replaces Zigpollv0.1.0MITPython 3.12

What you get

  • 21/21 checks passing on both the contract port and an override port
  • Four distinct question types, not one generic type
  • Public response id separated from admin credentials
  • HMAC-SHA256 signed webhooks, bad signature rejected
  • HTTPS-only webhook destinations
  • Aggregates verified against raw rows
  • No baked password: startup fails with setup instructions

Surveys

Create, update and list surveys with single choice, multi choice, rating and free-text questions.

Public responses

Anonymous responses go to a public survey id with no auth, keeping the admin credential out of the browser.

Signed webhooks

Response events are HMAC-SHA256 signed over the raw body with a per-survey secret, and plain HTTP destinations are refused.

Analytics

Per-survey aggregates and CSV export, checked against the raw response rows.

No default secret

First boot requires ZIGPOLL_ADMIN_PASSWORD and fails with instructions if absent.

Interface#

Admin console at / and public embed at /s/<public_id> on port 8630.

Install#

From a clean machine to a running server in four commands.

Requirements

  • Python 3.12 or newer
  • uv (Astral)
  • ZIGPOLL_ADMIN_PASSWORD set before first start

Step 1 · Clone

Get the source.

git clone https://github.com/venugopal1902/replicas.git
cd replicas/services/zigpoll-engine

Step 2 · Install

Create the environment.

uv sync

Step 3 · Set the admin password

Required on first start. No default ships.

export ZIGPOLL_ADMIN_PASSWORD='choose-a-long-unique-password'

Step 4 · Run

Admin console on port 8630.

uv run python scripts/run_server.py

Run the suite

cd services/zigpoll-engine
ZIGPOLL_TEST_PORT=8631 uv run --with pytest --with httpx pytest tests/ -q

# recorded: 21 passed on 8630 and 21 passed on 8631

Usage#

Verify signed webhooks yourself

A bad signature must be refused. This is the check that the paid product actually enforces.

curl -s -o /dev/null -w '%{http_code}\n' -X POST http://127.0.0.1:8630/api/webhooks/test \
  -H 'Content-Type: application/json' \
  -H 'X-Zigpoll-Signature: sha256=deadbeef' \
  -d '{"survey_id":"demo"}'
# expect 401 or 403, never 200

Operational notes#

Read before going live. These are the things that break in production.
  • Zigpoll tier pricing is UNVERIFIED in the research snapshot, so no price ladder is claimed here.
  • No Shopify order context: the public id model is implemented, the Shopify embed is not.
  • The webhook receiver is a test endpoint. Wire your own consumer to validate signatures in production.

FAQ#

Why is the public survey id separate from the admin credential?

Because embedding an admin key in a storefront page would leak it to every visitor. The separation is the security property.

Does it need a Zigpoll account?

No. Everything runs locally.

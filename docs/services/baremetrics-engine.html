Baremetrics Engine

MRR, churn and MRR movement computed from subscription rows, not estimated.

Replaces Baremetrics Version 0.1.0 License MIT Runtime Python 3.12

Overview#

Baremetrics computes SaaS metrics from your billing provider. This engine computes the same headline numbers from subscription rows instead of estimating them: MRR and ARR as of a date, active count, ARPU, new and churned MRR over a 30-day window, net new MRR, revenue churn rate and quick ratio, plus a daily MRR series. Ingest is Stripe-shaped so a real webhook can point at it, and the test suite recomputes every headline metric independently from the raw rows so a wrong formula cannot pass.

replaces Baremetricsv0.1.0MITPython 3.12

What you get

  • 22/22 checks passing, metrics recomputed independently
  • Cancelled-today exits today's MRR, the classic overstatement bug
  • Daily MRR series for the last N days
  • Stripe-shaped webhook ingest
  • Idempotent cancellation
  • No baked password: startup fails with setup instructions

Metrics

MRR, ARR, active count, ARPU, new and churned MRR, net new, churn rate, quick ratio.

As-of dates

Every metric can be asked for a past date, and the MRR series walks day by day.

Ingest

Stripe-shaped subscription created/deleted events, plus a local API to add and cancel.

Console

Headline tiles plus a 30-day MRR bar chart rendered from the series endpoint.

Proof over prose

Tests recompute MRR, ARR, ARPU, new and churned MRR from raw rows and compare.

Interface#

Console at / on port 8650 with headline tiles and a 30-day MRR chart.

Install#

From a clean machine to a running server in four commands.

Requirements

  • Python 3.11 or newer
  • uv (Astral)
  • ADMIN_PASSWORD set before first start

Step 1 · Clone

Get the source.

git clone https://github.com/venugopal1902/replicas.git
cd replicas/services/baremetrics-engine

Step 2 · Install

Create the environment.

uv sync

Step 3 · Set the admin password

Required on first start.

export ADMIN_PASSWORD='choose-a-long-unique-password'

Step 4 · Run

Console on port 8650.

uv run python scripts/run_server.py

Run the suite with the server up

cd services/baremetrics-engine
uv run python tests/test_baremetrics.py

Usage#

Ask for metrics as of a past date

Every headline number accepts as_of, so a board deck can quote any month end.

TOKEN=$(curl -s -X POST http://127.0.0.1:8650/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@baremetrics.local","password":"your-password"}' | jq -r .token)

curl -s -H "Authorization: Bearer $TOKEN" \
  'http://127.0.0.1:8650/api/metrics/summary?as_of=2026-09-30' | jq '{mrrCents,arrCents,churnRatePct}'

Feed it a Stripe-shaped event

Point a real webhook here, or simulate one.

curl -s -X POST http://127.0.0.1:8650/webhooks/stripe \
  -H 'Content-Type: application/json' \
  -d '{"type":"customer.subscription.created","data":{"object":{"customer_email":"new@example.com","amount":4900,"plan":"growth"}}}'

Operational notes#

Read before going live. These are the things that break in production.
  • Baremetrics pricing was UNVERIFIED in our research pass, so no price ladder is claimed.
  • Churn is revenue churn, not logo churn. No per-plan or cohort views.
  • Webhook ingest trusts its payload. Put it behind your own signature check before exposing it.
  • Metrics are computed on read; at scale you would materialise daily snapshots.

FAQ#

Does it connect to Stripe directly?

No. It accepts Stripe-shaped webhooks. Point your Stripe endpoint here, or use the local API.

Why does a cancellation affect today's MRR?

Because counting a subscription the customer cancelled today overstates revenue. The tests assert this specific case.

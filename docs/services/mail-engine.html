Mail Engine

Cold email campaigns, sequences, inbox and tracking. Self-hosted, simulate-mode by default.

Replaces Instantly / Lemlist Version 0.1.0 License MIT Runtime Python 3.12

Overview#

Instantly and Lemlist sell cold-email sending from roughly $30 to $100+ per month, priced by mailbox count and lead volume. This engine reproduces the working surface: campaigns with ordered steps, lead import, enrolment, send-next execution, suppressions, bounce/unsubscribe handling, an inbox with replies, open and click tracking, mailbox warmup simulation, workspace analytics, and an MCP endpoint exposing eight tools. Sending defaults to simulate mode, so nothing leaves the machine until SMTP is configured.

replaces Instantly / Lemlistv0.1.0MITPython 3.12

What you get

  • 47 API operations across 35 paths

  • Simulate mode by default, never fakes a delivery

Leads

Deliverability

Mailbox warmup simulation with a run endpoint and progress state.

MCP

Eight tools: list/create campaigns, list/add leads, enrol, send-next, analytics.

Interface#

Console at / on port 8640.

Install#

From a clean machine to a running server in four commands.

Requirements

  • Python 3.12 or newer
  • uv (Astral)
  • No SMTP account needed for simulate mode

Step 1 · Clone

Get the source.

git clone https://github.com/venugopal1902/replicas.git
cd replicas/services/mail-engine

Step 2 · Install

Create the environment.

uv sync

Step 3 · Run

Console on port 8640.

uv run python scripts/run_server.py

Usage#

Run the whole loop from the CLI

Login, create a campaign, add a step, add a lead, enrol, then send the next due step.

TOKEN=$(curl -s -X POST http://127.0.0.1:8640/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"admin@mailengine.local","password":"mailengine123"}' | jq -r .token)

CID=$(curl -s -X POST http://127.0.0.1:8640/api/campaigns \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"Q4 outbound"}' | jq -r .id)

curl -s -X POST http://127.0.0.1:8640/api/campaigns/$CID/enroll \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"lead_ids":[]}'

curl -s -X POST http://127.0.0.1:8640/api/campaigns/$CID/send-next \
  -H "Authorization: Bearer $TOKEN"

Operational notes#

Read before going live. These are the things that break in production.
  • Sending defaults to simulate mode. Nothing is transmitted until SMTP is configured.
  • The 15 headless-Chrome UI checks in the repo are self-reported by the build agent and were not re-run by the maintainer.
  • Instantly and Lemlist tier pricing is not reproduced here; no price ladder is claimed.
  • Warmup is simulated, not a real deliverability reputation system.

FAQ#

Will it send real email?

Only if you configure SMTP. In the default simulate mode every send is recorded without transmission.

Does it replace an inbox provider?

No. It models an inbox for campaign replies. It does not connect to Gmail or Outlook.

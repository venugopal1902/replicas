Bannerbear Engine

Define a template once, render unlimited PNG variants. No $49-299/mo credit meter.

Replaces Bannerbear Version 0.1.0 License MIT Runtime Python 3.12

Overview#

Bannerbear sells credit-metered template image rendering from $49 to $299 a month. This engine reproduces the core: templates with named text and image layers, an async render queue that returns 202 and a job id, real PNG output at the template's dimensions, project-scoped bearer keys, and a credit ledger that refuses a render with 402 when the balance is empty. Image assets are uploaded locally, never fetched from a URL, which removes the SSRF surface.

replaces Bannerbearv0.1.0MITPython 3.12

What you get

  • 15 pytest checks passing
  • Independent render verified: PNG 1080x1350, 26089 bytes
  • Credit ledger debits exactly one unit per render
  • 402 when a project runs out of credits
  • Project keys shown once, stored hashed
  • No third-party rendering key required

Templates

Named text and image layers with position, size and colour, stored as JSON and validated before use.

Async renders

POST /api/renders returns 202 plus a job id, then poll queued, rendering, done or failed.

Credits

Each accepted render reserves a credit, writes a usage row, and refunds with a compensating row if the render fails.

Project keys

Admin issues per-project bearer keys, hashed at rest and printed once.

402 on empty

A project without credits is refused instead of being served for free.

Interface#

Admin console at /admin on port 8620.

Install#

From a clean machine to a running server in four commands.

Requirements

  • Python 3.12 or newer
  • uv (Astral)

Step 1 · Clone

Get the source.

git clone https://github.com/venugopal1902/replicas.git
cd replicas/services/bannerbear-engine

Step 2 · Install

Create the environment.

uv sync

Step 3 · Run

Console on port 8620.

uv run python scripts/run_server.py

Run the suite

cd services/bannerbear-engine
uv run --with pytest --with httpx --with pillow pytest tests/test_bannerbear.py -q

Usage#

Render a template variant

Templates are defined once; a render overrides only the layers you name.

JOB=$(curl -s -X POST http://127.0.0.1:8620/api/renders \
  -H "Authorization: Bearer $KEY" -H 'Content-Type: application/json' \
  -d '{"template_id":"'$TEMPLATE'","overrides":{"headline":{"text":"PROOF"}}}' | jq -r .job_id)

curl -s -H "Authorization: Bearer $KEY" -o out.png \
  http://127.0.0.1:8620/api/renders/$JOB/download

Operational notes#

Read before going live. These are the things that break in production.
  • PNG only. Video, animation and AI image generation are not implemented.
  • Image assets are uploaded locally, never fetched from a URL, which removes the SSRF surface.
  • Per-tier credit allotments were not published in the research, so they are not invented here.
  • BANNERBEAR_ADMIN_PASSWORD defaults to bannerbear123 on this build. Change it before exposing the port.

FAQ#

Does it need a Bannerbear account?

No. Rendering is local Pillow output. No third-party key is involved.

What happens when credits run out?

The render is refused with 402 instead of being served for free.
